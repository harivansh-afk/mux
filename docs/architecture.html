mux

A macOS-native terminal multiplexer on libghostty that speaks the ix shell protocol. Every pane is a GhosttyKit Metal surface; any pane can transparently be a session on an ix VM, a plain Linux box running muxd, or the Mac itself. No web layer, no sidebar, no chrome.

0. The one-paragraph thesis

ix already contains both halves of this product, unconnected: Stack A (ix shell / ix-console) is a remote shell protocol with a server-side headless ghostty that can hand a reattaching client its exact screen back; Stack B (ix-term) is a local multiplexer with zero remote support, rendered through a web stack. mux is the composition: Stack B's job done natively on macOS (GhosttyKit surfaces + a Swift split tree), with Stack A as the pane transport - and Stack A's server forked into muxd so the same protocol works on any Linux box, not just ix VMs. The wire protocol becomes an open API for "give me a terminal on that machine."

2. The wire protocol (forked, not invented)

Source of truth: ix/crates/ix/rpc/src/session/shell.rs (683 lines - the whole contract). Framing from ix/crates/rpc/transport/src/frame.rs (~300 lines needed of 8,051).

frame:   [u32 LE length][u8 lane][payload]

lanes in:   0 input (raw PTY bytes)   1 control (codec values)
lanes out:  0 opened                  1 output (raw PTY bytes)   2 events

handshake/control types (7, tiny, hand-rolled encoder ~200 lines):
Request       { vm_id, cols, rows, term, mode, env }
Mode          Create { command, default_shell } | Attach { session } | Peek { session } | List
ClientControl Resize { cols, rows } | Close
OpenSuccess   Attached { session } | Listed { sessions }
ServerEvent   Exit { code } | Detached
SessionInfo   { id, command, attached, exited }

PTY bytes travel only on raw byte lanes. The encoded values are handshake, control and status metadata. That is why this protocol is so forkable: the bulk of the wire is opaque bytes, and the seven control types are trivial to encode without ix's 6,000-line nightly-only codec crate (append-only #[wire(N)] slot table - we reimplement just enough, keeping byte-for-byte wire compat).

Why this is not ix-VM-exclusive

All the VM-specific machinery (QUIC ingress routing by DCID, Ed25519 JWT capability tokens, per-boot pinned TLS certs) is the outer transport between the ix CLI and ix-agent. The inner hop - ix-agent to ix-console - is plain TCP on 127.0.0.1:5001 with the same lane framing and a single bearer token read from /run/ix/console-token. So:

TargetTransportAuthServer
Mac (local panes)Unix socketfilesystem permsmuxd
Linux boxQUIC streams (quinn); local muxd brokers one connection per hostpinned self-signed cert (TOFU) + bearer token filemuxd (ix-console fork)

ix VM (v2)QUIC/WebTransport, native clientconnect token JWT + pinned certunmodified ix-console

ix VMs work on day one with zero protocol code: the pane's relay command is literally ix shell <vm>. The native QUIC client is a later refinement, not a prerequisite.

2.2 The muxd peer dialect, byte for byte

These bytes are locked by a golden test (crates/mux-proto/src/peer.rs::golden_wire_bytes) - the test is the spec. Handshake: attach-or-create pty "p1" at 120x40, TERM=xterm-ghostty, local:

handshake message = [u32 LE payload length][payload]
19 00 00 00                                        length = 25
78                                                 cols = 120        (u16, varint)
28                                                 rows = 40
01 0d 78 74 65 72 6d 2d 67 68 6f 73 74 74 79      term = Some, len 13, "xterm-ghostty"
00                                                 token = None (unix socket: fs perms are auth)
00                                                 target = None (this daemon serves it)
00                                                 mode = Open (discriminant 0)
02 70 31                                           name = len 2, "p1"
00                                                 cwd = None
00                                                 command = 0 args (login shell)

After the reply (OpenReply on egress lane 0) and the screen replay (raw bytes on egress lane 1), everything is lane frames. A resize control frame and an exit event, complete:

resize to 120x40, ingress lane 1:
04 00 00 00  01  00 78 28      [len=4][lane=1][Resize disc=0, cols=120, rows=40]

keystroke "g", ingress lane 0 (raw, no encoding ever):
02 00 00 00  00  67            [len=2][lane=0][0x67]

clean exit, egress lane 2:
03 00 00 00  02  00 00         [len=3][lane=2][Exit disc=0, code=0 zigzag]

PTY data - the hot path - is raw bytes on lanes 0/1 with zero serialization, in ix and in mux identically. Encoded values only ever appear on the control/event lanes, a few messages per session.

2.3 Remote: the same bytes inside a QUIC stream

UDP datagram
└─ QUIC connection (quinn, RFC 9000) - TLS 1.3, ALPN muxd/1, one per remote host
   ├─ bidi stream: pane A's connection   [u32 len][OpenRequest] + lane frames
   ├─ bidi stream: pane B's connection   exactly the unix-socket byte stream
   └─ bidi stream: control (list/kill)

One QUIC connection per host, one bidirectional stream per logical pane connection. The byte stream inside a stream is identical to the unix-socket stream, so the daemon has a single connection handler generic over any async byte pipe. Panes never dial the network: they attach to the local muxd over the unix socket with target = Some(host), and the local daemon relays the stream over its per-host connection. Reconnect and QUIC connection migration (wifi to LTE mid-session) therefore live in exactly one place. 0-RTT early data is disabled: replayable requests are not acceptable for a session protocol; every connection does a full 1-RTT handshake.

2.4 Security model (this replaces ssh for terminals)

PropertyMechanismssh equivalent
Channel cryptoTLS 1.3 inside QUIC (rustls): AEAD only, forward secrecy, no legacy versions to misconfiguressh transport layer
Server identityself-signed cert generated on first run (rcgen); client pins SHA-256 of the SPKI per host alias, trust-on-first-use, recorded in ~/.local/state/mux/known_hosts; hard fail on mismatch. The daemon logs its SPKI hash at startup for out-of-band verificationknown_hosts fingerprint pinning
Client authorization256-bit random client token, generated 0600 at ~/.local/state/mux/token, never copied anywhere; the daemon accepts any token whose SHA-256 digest is listed in its --authorized-tokens file (digests are not secrets - on NixOS they live in the flake via services.muxd.authorizedTokenDigests) or that matches its own ~/.local/state/muxd/token. A per-host override at ~/.local/state/mux/tokens/<host> still wins when present. Sent only inside the encrypted channel; digest compare, re-read per connectionauthorized_keys - and enrolled the same way: the client mints its identity, the host's config authorizes its fingerprint
Local planeunix socket, 0600, kernel-enforced same-uid; no token n/a (ssh has no local plane)
Attack surfaceone UDP port, one protocol, ~2k LOC of daemon, runs as the login usersshd: root daemon, PAM, subsystems, forwarding, config drift

What a network observer sees: opaque QUIC datagrams. What a MITM can do: nothing after first contact (the pin covers the key doing the channel crypto); on first contact, TOFU has the same window ssh has - verify the logged SPKI hash out-of-band if the first connection crosses hostile ground. What a stolen client token yields: attach rights to the daemons that authorized its digest; rotate by deleting ~/.local/state/mux/token and updating the digest in the flake. Deliberately absent: agent forwarding, port forwarding, multi-user auth, PAM - not needed for personal infra, and every absent feature is attack surface that does not exist.

3. Components

Mux.app Swift / AppKit the only UI

  • GhosttyKit (libghostty full embedding API, MIT): hand it an NSView, it renders Metal via its own IOSurface-backed layer and render thread. We never touch Metal, fonts, or VT parsing for display. ~4,800 lines of ghostty's own Swift glue (SurfaceView_AppKit.swift, Ghostty.App.swift) to adapt, not write.
  • Tiling: adapted from ghostty's MIT SplitTree.swift (1,413 lines, already Codable): indirect enum .leaf(view) / .split{direction, ratio, left, right}, Path addressing, Spatial CGRect mapping for directional focus, a zoomed node. Core ghostty has zero split logic - tiling is entirely ours, which is what we want.
  • Prefix engine: prefix is a mode among modes (normal / prefix / navigate / resize / copy), not a chord table. Bindings declare their own context ("prefix+n" vs "ctrl+alt+n"). Implemented as a local NSEvent monitor ahead of the focused surface. Includes the nvim-mux held-ctrl aliasing (C-b C-n ≡ C-b n) and edge-fallback pane motion.
  • Layout snapshots: versioned JSON. Restore layout and identity, not pixels.

muxd Rust ix-console fork

Fork of ix/crates/vm/guest/console/agent - keep ~2,500 of 4,289 LOC:

  • Keep: manager.rs (session table, 64 max, Arc-identity attach tokens), session.rs, pty*.rs (AsyncFd-based, no spawn_blocking), attach.rs, migrate.rs (SCM_RIGHTS live-PTY handoff to a successor process: daemon upgrades without killing sessions), the ghostty-vt crate (headless VT + render_reattach).
  • Drop: service-init (OTel/Prometheus/Sentry/axum - replace with tracing_subscriber::fmt()), vm-guest-* crates, guest passwd/PATH assumptions.
  • Fix in the fork: the attach race (screen dump rendered before the client channel is installed; bytes in the window are lost - upstream has a test proving it: missed_output_causes_divergence). Also: make migrate.rs carry a screen snapshot across restarts (upstream builds a fresh empty Terminal and loses scrollback).
  • Listen on: unix socket (local, 0600 - shipping in M2) and QUIC via quinn (remote, M3): each bidirectional stream is one logical connection (same handshake, same lanes - the handler is generic over any byte stream). Auth: self-signed cert generated on first run, client pins the key ssh-known-hosts style, plus a bearer token file re-read per connection. Panes never dial the network themselves: they attach to the LOCAL muxd, which brokers one QUIC connection per remote host and relays a stream per pane - reconnect and roaming (QUIC connection migration) live in one place.

mux-attach Rust ~500 LOC

The bridge that makes remote panes possible without forking ghostty: libghostty's only IO backend is exec (a closed Zig enum with one variant; no ghostty_surface_write exists). So each pane's command is mux-attach <target>: raw-mode stdio on one side, lane-framed protocol on the other. SIGWINCH → ClientControl::Resize. libghostty forks it against a real PTY and gets correct key encoding, resize, and rendering for free.

Steal from ix shell's client (interactive/terminal.rs): the RawModeGuard reset string, detach keys (C-], C-a d) with chunk-boundary-safe state, resize polling (200ms, because SIGWINCH coalesces during drags), the OSC 52/7717 relay scanner with its 2 MiB cap and open-rate gate.

mux-proto Rust ~800 LOC

Lane framing + the seven control types + a minimal slot-table encoder, wire-compatible with ix. Golden-byte tests against captures from a real ix VM keep us honest.

4. Tiling: exactly how it works

// state (Swift) - adapted from ghostty's SplitTree, Codable
enum Node {
  case leaf(PaneView)                       // NSView hosting a ghostty surface
  case split(direction: .horizontal|.vertical, ratio: Double, left: Node, right: Node)
}
// per workspace: root Node + zoomed: Path? + focused: Path
  1. Split (C-b ' / C-b -): replace the focused leaf with .split(leaf, newPane) at ratio 0.5. Layout pass walks the tree, assigns each leaf a CGRect, calls ghostty_surface_set_size. The surface's relay gets SIGWINCH; the daemon gets Resize; the remote PTY gets TIOCSWINSZ. One resize path end to end.
  2. Focus (C-b h/j/k/l): Spatial pass maps nodes to rects, picks the nearest rect in the direction, with tmux-style edge fallback (at the left edge, h wraps to the rightmost).
  3. Zoom (C-b z): set zoomed = focusedPath; layout renders one leaf full-bleed. Tree untouched.
  4. Resize mode (C-b r): h/j/k/l nudge the enclosing split's ratio; esc exits. Drag on divider does the same via SwiftUI.
  5. Persistence: the tree is Codable; snapshot per workspace. Subagent spiral heuristic from subagent-pane.sh (first split right at 0.38, then alternate off the previous pane at 0.5) comes along as the programmatic-split policy.

Two VTs in the path, one owner of truth. The daemon's headless ghostty-vt is the source of truth; the app-side libghostty surface is a renderer being replayed into. This is tmux-inside-ssh, done deliberately: pane scrollback belongs to the daemon, the client treats the reattach replay as content. Later upgrade path: the brand-new GHOSTSNP binary snapshot format (libghostty-vt, merged 2026-07/08, incremental decoder, READY marker for instant first paint) replaces the VT replay once it has a compat guarantee - Mitchell has said upstream is building reconnectable terminals on it.

9. Risks, honestly

  • libghostty embedding API is explicitly unstable ("not supported as a general purpose embedding API"). Mitigation: pin a commit, prebuilt-artifact CI, 100+ apps ship on it anyway.
  • ix wire compat is a moving target: no version field on the framing; compat rides on append-only slots. Mitigation: golden-byte tests against a live VM in CI; v1 uses ix shell as the relay so breakage is contained to M4.
  • Two-VT scrollback semantics: daemon owns truth, client scrollback is a replay artifact. Acceptable (it is tmux's model); GHOSTSNP later makes it exact.
  • Crowded space (muxy, agterm, cmux, forge...). The differentiator is not "multiplexer on libghostty" - it is native ix protocol + daemon-owned sessions on every target + the agent-session model. Nobody else has the protocol.
  • Known upstream bug, scoped: ix#10126 same-node QUIC hairpin (the ~52s workaround that plausibly killed the predecessor's ix integration, #408). muxd's remote QUIC (M3) is our own quinn client/server, so it does not inherit this; only the native ix-VM path (M4, ix's stack) does, until upstream fixes it. Keep the ix hop out of the demo path.

10. Decisions taken (defaults, revisit if wrong)

  • Swift + AppKit (not SwiftUI-first): window/NSView control matters more than declarative UI here; SwiftUI only for the divider/resize affordances, as ghostty does.
  • Local panes go through local muxd from M2 on (uniformity beats one fewer process; the relay adds one PTY + a few MB per pane).
  • Daemon-owned scrollback; client replay is content, not truth.
  • BSP tree with ratios (ghostty model), not dwindle autolayout (ix-term's term-tile stays available in-tree as an option later).
  • jj for VCS, colocated git for pushing to the forge.
  • Config: TOML, delta-only with annotated defaults via mux --default-config.
