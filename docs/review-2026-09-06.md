# Codebase review — 2026-09-06

Reviewed main at `7962a06`. The existing architecture is worth keeping:
Ghostty handles terminal semantics, muxd owns persistent PTYs, and the Swift
app owns layout. The most useful reductions remove duplicated knowledge
and unnecessary wrappers; moving those responsibilities would add risk.

## Codex titles: confirmed cause

Canvas reads `pane.agent.topic` from daemon metadata. On the running Mac,
Codex was detected but its topic was only the project name. On Spark, all
three attached Codex panes had `agent: null`. Their foreground process-group
leaders were `node …/bin/codex`; the native Codex processes were children.
The detector inspected only argv[0], so it classified the leaders as Node.

[PR #66](https://git.harivan.sh/harivansh-afk/mux/pulls/66) recognizes the
script argument of Node/Node.js/Bun launchers and initializes agent metadata
from restored terminals after adoption. It does not scan arbitrary arguments.
Real PTY tests cover title changes through list/watch and an idle adopted
agent with no new output. A standalone build of the actual classifier on
Spark recognized all three live Node launchers; its 38 tests passed there.

Separately, the installed Codex configuration omitted `thread-title`.
The checked local Codex source defaults to activity plus project name.
[Nix PR #608](https://git.harivan.sh/harivansh-afk/nix/pulls/608) adds
`terminal_title = ["activity", "thread-title", "project-name"]` at the
configuration source. Codex must restart after activation to load it;
`/rename` supplies a thread title when desired. Configuration and daemon
updates are both needed for the intended result on Spark.

## Follow-up risks, not reproduced failures

1. **Upgrade/socket ownership races:** ordinary CLI queries auto-spawn a
   daemon as soon as the control socket fails to connect. They could race
   the successor between predecessor exit and successor bind. The upgrade
   command avoids auto-spawn, but ordinary list/watch paths share `connect()`.
   Also test acknowledgment-write failures after a successful adoption.
2. **Evicted client resize:** teardown names the client identity, but the
   resize path should be tested while a stale handler is being evicted.
   A stale resize could reach the new attachment or block on its output.
3. **Snapshot validation:** decoding does not gate the version, and decoded
   split ratios bypass the documented range. Add malformed/future-version
   fixtures before choosing rejection versus repair, preserving recovery.
4. **Framing EOF:** sync and async lane readers treat a partial header EOF
   as a clean boundary, contrary to their contract. Pin the distinction with
   truncated-header fixtures before changing reconnect diagnostics.
5. **Large handoffs and authentication file races:** exercise platform FD
   limits near the configured 256-pane cap and simultaneous token/pin
   creation. No session loss or authentication bypass was demonstrated here.

The next worthwhile simplifications are the keyboard/action dispatch paths
and snapshot validation. They need observable behavior fixtures first;
removing the existing guards, manifest data, or recovery code merely to
shrink files would undermine the features this review is meant to preserve.
